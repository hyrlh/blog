本文整理 C++ 中的基本数据类型，也就是标准里常说的 **fundamental types**。

很多入门资料会把重点放在 `int`、`char`、`float`、`double` 上，但完整理解 C++ 基本类型时，还需要把 `void`、`nullptr` 的类型以及 `int32_t`、`size_t` 这类常见别名一起讲清楚。

## 1. C++ 基本数据类型总览

C++ 标准内建的基本类型主要可以分成几类：

```cpp
void
std::nullptr_t        // C++11，nullptr 的类型

bool

char
signed char
unsigned char
wchar_t
char8_t              // C++20
char16_t             // C++11
char32_t             // C++11

short
unsigned short
int
unsigned int
long
unsigned long
long long            // C++11 标准化
unsigned long long

float
double
long double
```

除此之外，C++ 还允许实现提供 **扩展整数类型** 和 **扩展浮点类型**。这些类型不是所有编译器都必须提供，使用时要看具体实现、标准库和编译选项。C++23 的 `<stdfloat>` 就是围绕可选扩展浮点类型提供标准化别名。

从大类上看，它们可以分为：

| 分类 | 类型 |
|---|---|
| 空类型 | `void` |
| 空指针类型 | `std::nullptr_t` |
| 布尔类型 | `bool` |
| 字符类型 | `char`、`signed char`、`unsigned char`、`wchar_t`、`char8_t`、`char16_t`、`char32_t` |
| 整数类型 | `short`、`int`、`long`、`long long` 以及对应的 `unsigned` 版本 |
| 浮点类型 | `float`、`double`、`long double`，以及实现可选提供的扩展浮点类型 |

严格来说，字符类型也属于整数类型体系的一部分，因为它们可以参与整数运算，也有对应的整数值。不过从使用语义上，字符类型通常单独讲。

## 2. `void` 和 `std::nullptr_t`

`void` 和 `std::nullptr_t` 经常都和“没有东西”有关，但它们表达的是完全不同的概念。

### 2.1 `void`：表示没有值

`void` 表示“没有值”。

最常见的场景是函数没有返回值：

```cpp
void print_message()
{
    // 做一些事情，但不返回结果
}
```

`void` 也常用于通用指针 `void*`：

```cpp
void* p = nullptr;
```

但是要注意，`void` 和 `void*` 不是一回事：

| 写法 | 含义 |
|---|---|
| `void` | 空类型，表示没有值 |
| `void*` | 指向未知类型对象的指针 |

不能定义一个普通的 `void` 变量：

```cpp
void x; // 错误：void 不能作为普通变量类型
```

### 2.2 `std::nullptr_t`：`nullptr` 的类型

C++11 引入了 `nullptr`，它是空指针字面量。

`nullptr` 的类型是 `std::nullptr_t`：

```cpp
#include <cstddef>

std::nullptr_t p = nullptr;
```

`nullptr` 可以转换成任意指针类型：

```cpp
int* p1 = nullptr;
double* p2 = nullptr;
char* p3 = nullptr;
```

也可以转换成成员指针类型：

```cpp
struct User {
    int id;
};

int User::* member = nullptr;
```

但是 `nullptr` 不是整数，不应该把它当成 `0` 使用：

```cpp
int n = nullptr; // 错误
```

### 2.3 `void` 和 `std::nullptr_t` 的区别

| 对比项 | `void` | `std::nullptr_t` |
|---|---|---|
| 表达含义 | 没有值 | 空指针字面量的类型 |
| 是否能定义普通变量 | 不能 | 可以 |
| 典型值 | 没有值 | `nullptr` |
| 常见用途 | 无返回值函数、`void*` 通用指针 | 表示空指针、重载区分空指针 |
| C++ 版本 | C++ 一直支持 | C++11 引入 |

### 2.4 建议使用场景

使用 `void` 的场景：

```cpp
void log_error();
void* raw_memory;
```

适合：

- 函数不需要返回值。
- 和 C 风格接口、底层内存接口交互时使用 `void*`。
- 表达“这个函数只做动作，不产生结果”。

使用 `nullptr` / `std::nullptr_t` 的场景：

```cpp
int* p = nullptr;
```

适合：

- 初始化指针为空。
- 判断指针是否为空。
- 需要明确传递“空指针”。
- 写重载函数时区分 `0` 和空指针。

示例：

```cpp
#include <iostream>
#include <cstddef>

void f(int)
{
    std::cout << "int\n";
}

void f(std::nullptr_t)
{
    std::cout << "nullptr\n";
}

int main()
{
    f(0);       // 调用 f(int)
    f(nullptr); // 调用 f(std::nullptr_t)
}
```

结论：现代 C++ 中，空指针优先使用 `nullptr`，不要再用 `NULL` 或 `0` 表示空指针。

## 3. 布尔类型 `bool`

`bool` 表示逻辑值，只有两个取值：

```cpp
bool ok = true;
bool failed = false;
```

常用于条件判断：

```cpp
if (ok) {
    // ...
}
```

`bool` 可以和整数发生隐式转换：

```cpp
bool a = 1;  // true
bool b = 0;  // false
int n = true; // 1
```

但是从代码可读性上，不建议用 `int` 代替 `bool`。如果一个变量只有“是/否”“开启/关闭”“成功/失败”两种语义，就应该使用 `bool`。

## 4. 字符类型

C++ 的字符类型比很多人想象中复杂。它们不只是 `char`，还包括宽字符和不同 Unicode 编码单元类型。

### 4.1 字符类型列表

| 类型 | 引入版本 | 主要用途 |
|---|---|---|
| `char` | C++ 一直支持 | 普通字符、窄字符串、字节数据 |
| `signed char` | C++ 一直支持 | 明确有符号的 1 字节整数 |
| `unsigned char` | C++ 一直支持 | 明确无符号的 1 字节整数、原始字节 |
| `wchar_t` | C++ 一直支持 | 宽字符，大小和编码依平台而定 |
| `char8_t` | C++20 | UTF-8 代码单元 |
| `char16_t` | C++11 | UTF-16 代码单元 |
| `char32_t` | C++11 | UTF-32 代码单元 |

字符字面量和字符串字面量的 `L`、`u8`、`u`、`U`、`R` 等前缀，本文统一放在第 8 节“基本类型字面量前缀和后缀小结”中讲，这样可以和整数、浮点、布尔、空指针字面量一起理解。

### 4.2 `char`、`signed char`、`unsigned char` 是整型还是字符型？

答案是：它们既有字符类型身份，也有整数类型行为。

更准确地说：

- `char`、`signed char`、`unsigned char` 是三种不同的类型。
- 它们都属于字符类型。
- 它们也都是整数类型体系的一部分，可以参与整数运算。
- `signed char` 和 `unsigned char` 明确指定了有符号和无符号。
- `char` 是否有符号由编译器和平台决定。

示例：

```cpp
char a = 'A';
signed char b = 65;
unsigned char c = 65;

int x = a + 1;
int y = b + 1;
int z = c + 1;
```

这段代码是合法的，因为字符类型可以提升为整数参与运算。

但是语义上最好区分：

```cpp
char ch = 'A';              // 表示字符
unsigned char byte = 0xFF;  // 表示原始字节
signed char small = -1;     // 表示小整数
```

### 4.3 `char` 和 `signed char` 不是同一个类型

很多人以为 `char` 就是 `signed char`，这是不准确的。

```cpp
char a = 'A';
signed char b = 'A';
unsigned char c = 'A';
```

这三个变量可能在内存表示上很像，但它们的类型不同。

在函数重载里也能看出来：

```cpp
void f(char);
void f(signed char);
void f(unsigned char);
```

这是三个不同的重载。

`char` 的有符号性由实现决定：

```cpp
char c = -1; // 在某些平台上行为符合预期，在某些平台上可能不是你想要的
```

如果你需要表达小整数，应该明确写：

```cpp
signed char x = -1;
unsigned char y = 255;
```

如果你需要表达文本字符，使用：

```cpp
char ch = 'A';
```

如果你需要表达原始字节，现代 C++ 也可以考虑：

```cpp
#include <cstddef>

std::byte b{0xFF};
```

不过 `std::byte` 是 C++17 的库类型，不是基本数据类型。

### 4.4 `wchar_t` 是什么？

`wchar_t` 是 C++ 的内建基本类型，用来表示宽字符。

```cpp
wchar_t wc = L'中';
const wchar_t* text = L"中文";
```

`wchar_t` 的重点在于：它是平台相关的。

| 平台 | 常见大小 | 常见编码习惯 |
|---|---|---|
| Windows | 2 字节 | 常用于 UTF-16 代码单元 |
| Linux/macOS | 4 字节 | 常用于 UTF-32 代码单元 |

这意味着：

```cpp
sizeof(wchar_t)
```

在不同平台上可能不同。

因此，`wchar_t` 并不是跨平台 Unicode 处理的完美答案。如果你需要明确表达编码单元，通常更推荐：

```cpp
char8_t   // UTF-8，C++20
char16_t  // UTF-16，C++11
char32_t  // UTF-32，C++11
```

当然，在 Windows API 编程中，`wchar_t` 和 `L"..."` 仍然非常常见。

### 4.5 字符类型使用建议

| 场景 | 建议类型 |
|---|---|
| 普通 ASCII 字符 | `char` |
| 普通窄字符串 | `char` / `std::string` |
| 原始字节 | `unsigned char` 或 `std::byte` |
| Windows 宽字符 API | `wchar_t` |
| 明确 UTF-8 代码单元 | `char8_t`，C++20 |
| 明确 UTF-16 代码单元 | `char16_t` |
| 明确 UTF-32 代码单元 | `char32_t` |

## 5. 整数类型

C++ 标准整数类型包括有符号和无符号两组。

### 5.1 有符号整数类型

| 标准写法 | 常见简写 |
|---|---|
| `signed char` | 无 |
| `short int` | `short` |
| `int` | `signed`、`signed int` |
| `long int` | `long` |
| `long long int` | `long long` |

示例：

```cpp
signed char a = -1;
short b = -2;
int c = -3;
long d = -4L;
long long e = -5LL;
```

### 5.2 无符号整数类型

| 标准写法 | 常见简写 |
|---|---|
| `unsigned char` | 无 |
| `unsigned short int` | `unsigned short` |
| `unsigned int` | `unsigned` |
| `unsigned long int` | `unsigned long` |
| `unsigned long long int` | `unsigned long long` |

示例：

```cpp
unsigned char a = 255;
unsigned short b = 65535;
unsigned int c = 100U;
unsigned long d = 100UL;
unsigned long long e = 100ULL;
```

### 5.3 `int`、`short`、`long` 的大小固定吗？

不固定。

C++ 标准没有规定 `int` 必须是 4 字节，也没有规定 `long` 必须是 8 字节。标准规定的是相对范围和最小能力。

常见 64 位平台上通常是：

| 类型 | 常见大小 |
|---|---|
| `char` | 1 字节 |
| `short` | 2 字节 |
| `int` | 4 字节 |
| `long` | Windows 常见 4 字节，Linux/macOS 常见 8 字节 |
| `long long` | 8 字节 |

如果你需要在当前平台查看真实大小，可以写：

```cpp
#include <iostream>

int main()
{
    std::cout << sizeof(char) << '\n';
    std::cout << sizeof(short) << '\n';
    std::cout << sizeof(int) << '\n';
    std::cout << sizeof(long) << '\n';
    std::cout << sizeof(long long) << '\n';
}
```

如果你需要查看范围，可以使用：

```cpp
#include <iostream>
#include <limits>

int main()
{
    std::cout << std::numeric_limits<int>::min() << '\n';
    std::cout << std::numeric_limits<int>::max() << '\n';
}
```

### 5.4 有符号和无符号的选择

有符号整数可以表示负数：

```cpp
int a = -10;
```

无符号整数不能表示负数：

```cpp
unsigned int b = 10;
```

无符号类型适合表达位模式、掩码、底层二进制数据：

```cpp
unsigned int flags = 0b1010;
```

但是不要因为“数量不会是负数”就盲目使用无符号类型。无符号类型在减法和比较中容易出现隐藏问题：

```cpp
unsigned int x = 0;
std::cout << x - 1 << '\n'; // 不会得到 -1，而是发生无符号回绕
```

日常业务计数如果不涉及标准库接口或位运算，很多时候使用 `int` 更简单。

## 6. 浮点类型

C++ 标准浮点类型有三个：

```cpp
float
double
long double
```

| 类型 | 常见大小 | 说明 |
|---|---|---|
| `float` | 4 字节 | 单精度浮点 |
| `double` | 8 字节 | 双精度浮点，默认推荐 |
| `long double` | 8、12 或 16 字节等 | 扩展精度，依平台而定 |

示例：

```cpp
float f = 3.14f;
double d = 3.14;
long double ld = 3.14L;
```

注意字面量后缀：

| 写法 | 类型 |
|---|---|
| `3.14f` | `float` |
| `3.14` | `double` |
| `3.14L` | `long double` |

一般建议：

- 默认使用 `double`。
- 内存敏感、性能敏感、大规模数组、图形图像、音视频处理场景可以考虑 `float`。
- 需要更高精度时再考虑 `long double`，并注意不同平台表现不同。

## 7. C++11 和之后新增的相关类型

很多资料会把 `wchar_t` 和 C++11 混在一起讲，但要注意：

```cpp
wchar_t
```

不是 C++11 新增。它在早期 C++ 中就已经是内建基本类型。

C++11 相关的重点是：

```cpp
long long
unsigned long long

char16_t
char32_t

nullptr
std::nullptr_t
```

C++20 又新增了：

```cpp
char8_t
```

C++23 增加了 `<stdfloat>` 中的固定宽度浮点类型别名，例如：

```cpp
std::float16_t
std::float32_t
std::float64_t
std::float128_t
std::bfloat16_t
```

这些浮点类型别名是可选的，只有实现支持对应的扩展浮点类型时才会提供。

还有一个前沿点：当前 C++26 工作草案把反射相关的 `std::meta::info` 也放在 fundamental types 条款中。它属于反射设施，不是日常“基本数据类型”入门主线。本文主体仍以 C++23 及主流 C++11/C++20 内容为主。

## 8. 基本类型字面量前缀和后缀小结

C++ 里很多值可以直接写成字面量：

```cpp
42
3.14
'A'
"hello"
true
nullptr
```

有些字面量前面或后面可以加前缀、后缀。它们不是装饰，而是在告诉编译器：

1. 这个字面量按什么进制、编码或格式解释。
2. 这个字面量的类型应该优先是什么。
3. 这个字面量参与重载解析时应该匹配哪个函数。

### 8.1 字符和字符串字面量前缀

不同字符类型对应不同的字面量前缀。

```cpp
char c = 'A';
wchar_t wc = L'A';
char16_t c16 = u'A';
char32_t c32 = U'A';
```

常见字符字面量和字符串字面量前缀如下：

| 写法 | 字符字面量类型 | 字符串字面量类型 | 说明 |
|---|---|---|---|
| `'A'` / `"ABC"` | `char` | `const char[N]` | 普通字符、普通窄字符串 |
| `L'A'` / `L"ABC"` | `wchar_t` | `const wchar_t[N]` | 宽字符、宽字符串 |
| `u8'A'` / `u8"ABC"` | C++20 起为 `char8_t` | C++20 起为 `const char8_t[N]` | UTF-8 代码单元 |
| `u'A'` / `u"ABC"` | `char16_t` | `const char16_t[N]` | UTF-16 代码单元 |
| `U'A'` / `U"ABC"` | `char32_t` | `const char32_t[N]` | UTF-32 代码单元 |
| `R"(ABC)"` | 不适用 | `const char[N]` | 原始字符串，不处理普通转义 |
| `LR"(ABC)"` | 不适用 | `const wchar_t[N]` | 宽原始字符串 |
| `u8R"(ABC)"` | 不适用 | C++20 起为 `const char8_t[N]` | UTF-8 原始字符串 |
| `uR"(ABC)"` | 不适用 | `const char16_t[N]` | UTF-16 原始字符串 |
| `UR"(ABC)"` | 不适用 | `const char32_t[N]` | UTF-32 原始字符串 |

版本细节：

- `u"..."` 和 `U"..."` 是 C++11 引入的 Unicode 字符串字面量。
- `u8"..."` 是 C++11 引入的 UTF-8 字符串字面量；C++20 前类型是 `const char[N]`，C++20 起类型是 `const char8_t[N]`。
- `u8'A'` 是 C++17 引入的 UTF-8 字符字面量；C++20 前类型是 `char`，C++20 起类型是 `char8_t`。
- `R"(...)` 是 C++11 引入的原始字符串字面量，适合正则表达式、Windows 路径、多行文本等场景。

原始字符串示例：

```cpp
const char* path1 = "C:\\Users\\name\\file.txt";
const char* path2 = R"(C:\Users\name\file.txt)";
```

`path1` 和 `path2` 表达的内容相同，但 `R"(...)` 里面不需要把每个反斜杠写成 `\\`。

### 8.2 字符前缀为什么会影响函数重载？

因为前缀决定了字面量的类型。

```cpp
#include <iostream>

void print(const char*)
{
    std::cout << "char string\n";
}

void print(const wchar_t*)
{
    std::cout << "wchar_t string\n";
}

int main()
{
    print("hello");   // 调用 const char* 版本
    print(L"hello");  // 调用 const wchar_t* 版本
}
```

如果不写 `L`，`"hello"` 就是普通窄字符串，不会自动变成 `wchar_t` 字符串。

同理：

```cpp
void f(const char16_t*);
void f(const char32_t*);

f(u"hello"); // char16_t 字符串
f(U"hello"); // char32_t 字符串
```

所以，字符和字符串前缀的本质不是“赋值语法要求”，而是“你正在创建哪一种类型的字面量”。

### 8.3 整数字面量的进制前缀

整数前缀主要决定进制。

| 写法 | 进制 | 示例 | 十进制值 |
|---|---|---|---|
| `42` | 十进制 | `42` | 42 |
| `052` | 八进制 | `052` | 42 |
| `0x2A` / `0X2A` | 十六进制 | `0x2A` | 42 |
| `0b101010` / `0B101010` | 二进制，C++14 | `0b101010` | 42 |

八进制前缀 `0` 很容易误伤：

```cpp
int a = 10; // 十进制 10
int b = 010; // 八进制 10，也就是十进制 8
```

日常代码中，除非你明确需要八进制，否则不要给整数随手加前导 `0`。

C++14 起，数字中可以使用单引号作为分隔符，提升可读性：

```cpp
int n = 1'000'000;
unsigned mask = 0b1111'0000;
```

这个 `'` 分隔符不改变类型，也不改变数值。

### 8.4 整数字面量的类型后缀

整数后缀主要决定有符号性和最小候选类型。

| 后缀 | 倾向类型 | 示例 |
|---|---|---|
| 无后缀 | `int`、`long`、`long long` 等第一个能容纳该值的类型 | `42` |
| `u` / `U` | 无符号整数 | `42u` |
| `l` / `L` | `long` | `42L` |
| `ll` / `LL` | `long long`，C++11 | `42LL` |
| `ul` / `UL` | `unsigned long` | `42UL` |
| `ull` / `ULL` | `unsigned long long`，C++11 | `42ULL` |
| `z` / `Z` | `std::size_t` 的有符号版本，C++23 | `42z` |
| `uz` / `UZ` | `std::size_t`，C++23 | `42uz` |

示例：

```cpp
auto a = 42;    // 通常是 int
auto b = 42u;   // unsigned int
auto c = 42L;   // long
auto d = 42LL;  // long long
auto e = 42ULL; // unsigned long long
```

注意：整数前面的 `-` 不是整数字面量的一部分。

```cpp
auto x = -42;
```

这里可以理解成对字面量 `42` 应用一元负号运算符。

### 8.5 浮点字面量后缀

浮点字面量默认是 `double`。

| 写法 | 类型 |
|---|---|
| `3.14f` / `3.14F` | `float` |
| `3.14` | `double` |
| `3.14l` / `3.14L` | `long double` |

示例：

```cpp
float f = 3.14f;
double d = 3.14;
long double ld = 3.14L;
```

C++23 的 `<stdfloat>` 如果提供对应扩展浮点类型，也会提供相应浮点字面量后缀：

| 后缀 | 对应类型，条件支持 |
|---|---|
| `f16` / `F16` | `std::float16_t` |
| `f32` / `F32` | `std::float32_t` |
| `f64` / `F64` | `std::float64_t` |
| `f128` / `F128` | `std::float128_t` |
| `bf16` / `BF16` | `std::bfloat16_t` |

这些不是所有编译器都支持。使用前应该检查对应的特性宏，例如：

```cpp
#include <stdfloat>

#ifdef __STDCPP_FLOAT32_T__
std::float32_t x = 1.0f32;
#endif
```

### 8.6 布尔、空指针和 `void` 有没有前缀后缀？

`bool` 的字面量只有：

```cpp
true
false
```

它们不需要前缀或后缀。

空指针字面量是：

```cpp
nullptr
```

它的类型是 `std::nullptr_t`。

`void` 没有普通值，也没有对应的字面量。`void` 表达的是“没有值”，常见于函数返回类型：

```cpp
void log();
```

需要特别注意：

```cpp
NULL
```

不是 C++ 语言的空指针字面量。它是标准库宏，历史上可能展开成 `0`、`0L` 或其他空指针常量形式。现代 C++ 中应该优先使用 `nullptr`。

## 9. `int32_t`、`size_t` 这些是基本数据类型吗？

不是。

`std::int32_t`、`std::uint64_t`、`std::size_t` 这些都很常见，但它们不是新的语言内建基本类型。它们是标准库提供的类型别名，背后仍然对应某个整数类型或扩展浮点类型。

基本类型和类型别名的区别可以先这样理解：

```cpp
int           // C++ 语言本身的基本类型
std::int32_t  // 标准库给“精确 32 位有符号整数类型”起的名字
std::size_t   // 标准库给“能表示对象大小的无符号整数类型”起的名字
```

### 9.1 `std::int32_t`

`std::int32_t` 定义在头文件 `<cstdint>` 中：

```cpp
#include <cstdint>

std::int32_t x = 100;
```

它表示“精确 32 位的有符号整数”。

注意几个重点：

1. `std::int32_t` 是类型别名，不是新的内建基本类型。
2. 它通常是 `int` 的别名，但不保证一定是 `int`。
3. 只有当平台存在精确 32 位、且没有填充位的整数类型时，标准库才提供它。

例如，在常见平台上它可能类似于：

```cpp
using int32_t = int;
```

也可能在某些平台上是：

```cpp
using int32_t = long;
```

所以它和 `int` 的区别主要是语义：

| 类型 | 语义 |
|---|---|
| `int` | 自然整数类型，大小由平台决定，标准保证至少 16 位，现代平台通常是 32 位 |
| `std::int32_t` | 明确要求精确 32 位有符号整数 |

适合使用 `std::int32_t` 的场景：

- 网络协议字段。
- 二进制文件格式。
- 跨平台存储格式。
- 硬件寄存器、外设协议。
- 需要明确整数位宽的接口。

示例：

```cpp
#include <cstdint>

struct PacketHeader {
    std::int32_t version;
    std::int32_t body_size;
};
```

如果只是在普通业务逻辑里表示计数、年龄、分数等，通常直接使用 `int` 即可。

### 9.2 `<cstdint>` 中的整数类型别名

`<cstdint>` 主要提供几组整数类型别名。

第一组：精确宽度整数类型。

| 类型 | 含义 | 是否总是存在 |
|---|---|---|
| `std::int8_t` | 精确 8 位有符号整数 | 条件提供 |
| `std::int16_t` | 精确 16 位有符号整数 | 条件提供 |
| `std::int32_t` | 精确 32 位有符号整数 | 条件提供 |
| `std::int64_t` | 精确 64 位有符号整数 | 条件提供 |
| `std::uint8_t` | 精确 8 位无符号整数 | 条件提供 |
| `std::uint16_t` | 精确 16 位无符号整数 | 条件提供 |
| `std::uint32_t` | 精确 32 位无符号整数 | 条件提供 |
| `std::uint64_t` | 精确 64 位无符号整数 | 条件提供 |

“条件提供”的意思是：如果实现提供对应位宽、且没有填充位的整数类型，就必须声明对应别名；否则可以没有。

常见桌面和服务器平台一般都会提供这些类型。

`std::int8_t` 和 `std::uint8_t` 需要特别注意：它们在很多实现上分别是 `signed char` 和 `unsigned char` 的别名。因此直接用 `std::cout` 输出时，可能按字符而不是数字显示。

```cpp
#include <cstdint>
#include <iostream>

std::uint8_t x = 65;

std::cout << x << '\n';              // 可能输出字符 A
std::cout << static_cast<int>(x) << '\n'; // 输出数字 65
```

第二组：至少 N 位的最小整数类型。

| 类型 | 含义 |
|---|---|
| `std::int_least8_t` | 至少 8 位的最小有符号整数类型 |
| `std::int_least16_t` | 至少 16 位的最小有符号整数类型 |
| `std::int_least32_t` | 至少 32 位的最小有符号整数类型 |
| `std::int_least64_t` | 至少 64 位的最小有符号整数类型 |
| `std::uint_least8_t` | 至少 8 位的最小无符号整数类型 |
| `std::uint_least16_t` | 至少 16 位的最小无符号整数类型 |
| `std::uint_least32_t` | 至少 32 位的最小无符号整数类型 |
| `std::uint_least64_t` | 至少 64 位的最小无符号整数类型 |

这组类型适合“我至少需要 N 位，但更关心省空间”的场景。

第三组：至少 N 位的最快整数类型。

| 类型 | 含义 |
|---|---|
| `std::int_fast8_t` | 至少 8 位的最快有符号整数类型 |
| `std::int_fast16_t` | 至少 16 位的最快有符号整数类型 |
| `std::int_fast32_t` | 至少 32 位的最快有符号整数类型 |
| `std::int_fast64_t` | 至少 64 位的最快有符号整数类型 |
| `std::uint_fast8_t` | 至少 8 位的最快无符号整数类型 |
| `std::uint_fast16_t` | 至少 16 位的最快无符号整数类型 |
| `std::uint_fast32_t` | 至少 32 位的最快无符号整数类型 |
| `std::uint_fast64_t` | 至少 64 位的最快无符号整数类型 |

这组类型适合“我至少需要 N 位，并希望实现选择更快类型”的场景。不过在现代业务代码里，这组类型不如 `int`、`std::int32_t`、`std::size_t` 常见。

第四组：最大宽度整数类型。

| 类型 | 含义 |
|---|---|
| `std::intmax_t` | 标准库提供的最大宽度有符号整数类型 |
| `std::uintmax_t` | 标准库提供的最大宽度无符号整数类型 |

它们适合写通用库、格式转换、需要容纳多种整数类型的场景。日常业务代码不需要为了“更大”而默认使用它们；如果协议或文件格式要求精确位宽，仍然应该优先使用 `std::int32_t`、`std::uint64_t` 这类精确宽度别名。

第五组：能保存指针值的整数类型。

| 类型 | 含义 | 是否总是存在 |
|---|---|---|
| `std::intptr_t` | 能保存 `void*` 指针值的有符号整数类型 | 条件提供 |
| `std::uintptr_t` | 能保存 `void*` 指针值的无符号整数类型 | 条件提供 |

这组类型适合底层代码、哈希、调试输出、系统接口等场景。不要把它们当成普通指针替代品；指针和整数之间的转换依然需要谨慎。

### 9.3 `<cstdint>` 里的宏不是类型

`<cstdint>` 还提供很多宏，例如：

```cpp
INT32_MIN
INT32_MAX
UINT32_MAX
INT64_C(123)
UINT64_C(123)
```

这些是范围宏或常量构造宏，不是类型。

常见用途：

```cpp
#include <cstdint>
#include <iostream>

std::cout << INT32_MIN << '\n';
std::cout << INT32_MAX << '\n';

auto x = UINT64_C(123);
```

如果是在 C++ 代码中查看类型范围，通常更推荐使用 `<limits>`：

```cpp
#include <limits>
#include <cstdint>

auto min_value = std::numeric_limits<std::int32_t>::min();
auto max_value = std::numeric_limits<std::int32_t>::max();
```

### 9.4 `std::size_t`

`std::size_t` 通常定义在 `<cstddef>` 中，很多其他头文件也会间接提供它：

```cpp
#include <cstddef>

std::size_t n = 10;
```

它表示“对象大小或内存大小”所需要的无符号整数类型。

`sizeof` 的结果就是 `std::size_t`：

```cpp
std::size_t n = sizeof(int);
```

标准库容器的大小也通常使用 `std::size_t`：

```cpp
#include <vector>

std::vector<int> values{1, 2, 3};
std::size_t count = values.size();
```

`std::size_t` 的特点：

1. 它是类型别名，不是新的基本数据类型。
2. 它是无符号整数类型。
3. 它足够表示当前平台上理论上可能对象的大小。
4. 它的具体底层类型由平台决定。

常见平台上，`std::size_t` 可能是：

```cpp
using size_t = unsigned long;
```

或者：

```cpp
using size_t = unsigned long long;
```

### 9.5 `std::size_t` 的使用注意

因为 `std::size_t` 是无符号类型，所以它也有无符号整数的常见问题。

例如：

```cpp
#include <vector>
#include <cstddef>

std::vector<int> values;
std::size_t n = values.size();

if (n - 1 > 0) {
    // 当 n == 0 时，n - 1 会发生无符号回绕
}
```

更稳妥的写法：

```cpp
if (n > 1) {
    // ...
}
```

循环时也要注意：

```cpp
for (std::size_t i = 0; i < values.size(); ++i) {
    // 正向遍历通常没问题
}
```

反向遍历不要这样写：

```cpp
for (std::size_t i = values.size() - 1; i >= 0; --i) {
    // 错误：i 是无符号类型，i >= 0 永远成立
}
```

可以改成：

```cpp
for (std::size_t i = values.size(); i-- > 0;) {
    // 使用 values[i]
}
```

或者直接使用反向迭代器：

```cpp
for (auto it = values.rbegin(); it != values.rend(); ++it) {
    // 使用 *it
}
```

C++20 还提供了 `std::ssize`，可以得到有符号的大小值：

```cpp
#include <iterator>
#include <vector>

std::vector<int> values{1, 2, 3};
auto n = std::ssize(values); // 通常是 std::ptrdiff_t
```

### 9.6 `<cstddef>` 中的常见类型别名

`<cstddef>` 和基本类型关系很密切，常见类型如下：

| 类型 | 是否基本类型 | 含义 |
|---|---|---|
| `std::size_t` | 否 | `sizeof` 结果类型，用于对象大小、容器大小 |
| `std::ptrdiff_t` | 否 | 两个指针相减的结果类型，有符号整数 |
| `std::nullptr_t` | 是，指 `decltype(nullptr)` 对应的空指针类型 | `nullptr` 的类型 |
| `std::max_align_t` | 否 | 对齐要求至少和所有标量类型一样严格的平凡标准布局类型 |
| `std::byte` | 否 | C++17，表示字节的 `enum class` |

其中 `std::ptrdiff_t` 经常和指针差值、迭代器差值相关：

```cpp
#include <cstddef>

int arr[10];

std::ptrdiff_t diff = &arr[9] - &arr[0]; // 9
```

`std::byte` 不是整数类型，也不是字符类型，它用于表达“这是一段原始字节”：

```cpp
#include <cstddef>

std::byte b{0x2A};
```

如果你需要对字节做整数运算，需要显式转换：

```cpp
#include <cstddef>

int value = std::to_integer<int>(b);
```

### 9.7 C++23 `<stdfloat>` 中的浮点类型别名

C++23 引入 `<stdfloat>`，用于声明固定宽度浮点类型别名。它们都是条件提供的。

| 类型 | 含义 | 字面量后缀 | 是否总是存在 |
|---|---|---|---|
| `std::float16_t` | 16 位二进制浮点类型 | `f16` / `F16` | 条件提供 |
| `std::float32_t` | 32 位二进制浮点类型 | `f32` / `F32` | 条件提供 |
| `std::float64_t` | 64 位二进制浮点类型 | `f64` / `F64` | 条件提供 |
| `std::float128_t` | 128 位二进制浮点类型 | `f128` / `F128` | 条件提供 |
| `std::bfloat16_t` | 16 位 bfloat 浮点类型 | `bf16` / `BF16` | 条件提供 |

它们和 `<cstdint>` 里的整数别名有一个重要区别：

- `std::int32_t` 可能就是 `int` 的别名。
- `std::float32_t` 不能只是 `float` 的别名；它必须对应实现提供的扩展浮点类型。

因此，不要简单地把：

```cpp
std::float32_t
```

当成：

```cpp
float
```

的跨平台替代品。它更适合硬件、数值计算、机器学习、图形等明确依赖特定浮点格式的场景，并且需要检查编译器支持。

### 9.8 类型别名和基本类型的关系

| 类型 | 是否基本类型 | 来自哪里 | 本质 |
|---|---|---|---|
| `int` | 是 | 语言内建 | 标准整数类型 |
| `long` | 是 | 语言内建 | 标准整数类型 |
| `float` | 是 | 语言内建 | 标准浮点类型 |
| `double` | 是 | 语言内建 | 标准浮点类型 |
| `std::int32_t` | 否 | `<cstdint>` | 某个精确 32 位整数类型的别名 |
| `std::uint64_t` | 否 | `<cstdint>` | 某个精确 64 位无符号整数类型的别名 |
| `std::size_t` | 否 | `<cstddef>` | 某个无符号整数类型的别名 |
| `std::ptrdiff_t` | 否 | `<cstddef>` | 某个有符号整数类型的别名 |
| `std::float32_t` | 否，别名本身不是新关键字 | `<stdfloat>` | 可选扩展浮点类型的别名 |
| `std::byte` | 否 | `<cstddef>` | `enum class`，用于表示字节 |

一句话总结：

```cpp
int              // 是 C++ 语言本身的基本类型
std::int32_t     // 是标准库给某个 32 位整数类型起的名字
std::size_t      // 是标准库给某个能表示对象大小的无符号整数类型起的名字
std::float32_t   // 是标准库给可选扩展浮点类型起的名字
```

## 10. 常见类型选择建议

类型选择不要只看“占几个字节”，更要看语义：这个值表示文本、字节、数量、索引、协议字段、内存大小，还是数学计算。

### 10.1 语言基本类型选择表

| 类型 | 推荐使用场景 | 注意事项 |
|---|---|---|
| `void` | 函数没有返回值；`void*` 用于底层通用指针 | 不能定义普通 `void` 变量 |
| `std::nullptr_t` / `nullptr` | 表示空指针；重载中区分空指针 | 现代 C++ 用 `nullptr`，不要用 `NULL` 或 `0` |
| `bool` | 是/否、开/关、成功/失败 | 不要用 `int` 表示布尔语义 |
| `char` | 普通窄字符、窄字符串元素 | `char` 是否有符号由实现决定 |
| `signed char` | 明确需要 1 字节有符号小整数 | 不要用它表达普通文本 |
| `unsigned char` | 原始字节、二进制缓冲区、底层内存观察 | 现代 C++ 表达纯字节也可考虑 `std::byte` |
| `wchar_t` | Windows 宽字符 API、历史宽字符接口 | 大小和编码依平台不同，不是跨平台 Unicode 万能解法 |
| `char8_t` | C++20 起明确表达 UTF-8 代码单元 | 不是“一个 Unicode 字符”，只是 UTF-8 代码单元 |
| `char16_t` | 明确表达 UTF-16 代码单元 | 一个 Unicode 字符可能需要两个 UTF-16 代码单元 |
| `char32_t` | 明确表达 UTF-32 代码单元 | 更直接表示 Unicode 码点，但空间占用更大 |
| `short` | 和历史 ABI、二进制布局、硬件接口匹配 | 普通整数计算不建议优先使用 |
| `unsigned short` | 和外部格式匹配的 16 位左右无符号字段 | 位宽仍以标准保证和平台实现为准 |
| `int` | 默认整数类型、普通循环计数、普通业务计算 | 标准只保证至少 16 位，现代平台通常 32 位 |
| `unsigned int` | 位掩码、标志位、底层无符号运算 | 避免和有符号数混合比较 |
| `long` | 需要匹配平台 ABI 或 C API 的 long | Windows 常见 32 位，Linux/macOS 64 位环境常见 64 位 |
| `unsigned long` | 匹配 C API、平台 ABI、位操作 | 跨平台位宽不固定 |
| `long long` | 需要至少 64 位的普通整数 | 如果协议要求精确 64 位，用 `std::int64_t` |
| `unsigned long long` | 需要至少 64 位的无符号整数、位运算 | 注意无符号回绕 |
| `float` | 大量浮点数据、图形、音视频、机器学习、内存带宽敏感场景 | 精度有限，不适合默认业务小数 |
| `double` | 默认浮点类型、普通科学计算、业务计算 | 小数仍有二进制浮点误差 |
| `long double` | 需要比 `double` 更高的实现相关精度 | 不同平台大小和精度差异明显 |

### 10.2 `<cstdint>` 整数别名选择表

| 类型 | 推荐使用场景 | 注意事项 |
|---|---|---|
| `std::int8_t` | 精确 8 位有符号字段 | 可能是 `signed char`，输出时可能表现像字符 |
| `std::uint8_t` | 精确 8 位无符号字段、字节序列、协议数据 | 可能是 `unsigned char`，输出数字时常需转换 |
| `std::int16_t` | 精确 16 位有符号协议字段、文件字段 | 条件提供，但常见平台都有 |
| `std::uint16_t` | 精确 16 位无符号协议字段、像素、端口等 | 注意大小端和序列化 |
| `std::int32_t` | 精确 32 位有符号协议字段、文件格式、跨平台存储 | 普通业务整数不必强行使用 |
| `std::uint32_t` | 精确 32 位无符号字段、位掩码、哈希值 | 算术回绕是定义良好的，但业务上未必正确 |
| `std::int64_t` | 精确 64 位有符号字段、时间戳、ID、文件偏移语义 | 不要默认用来替代所有整数 |
| `std::uint64_t` | 精确 64 位无符号字段、位模式、大 ID | 和有符号类型混用要小心 |
| `std::int_leastN_t` | 至少 N 位，并希望尽量省空间 | N 常见为 8、16、32、64 |
| `std::uint_leastN_t` | 至少 N 位的无符号省空间类型 | 不保证精确 N 位 |
| `std::int_fastN_t` | 至少 N 位，并希望实现选择较快类型 | 实际位宽可能大于 N |
| `std::uint_fastN_t` | 至少 N 位的较快无符号类型 | 不适合二进制布局字段 |
| `std::intmax_t` | 通用库中承接最大宽度有符号整数 | 不适合作为精确二进制布局字段 |
| `std::uintmax_t` | 通用库中承接最大标准无符号整数 | 输出、格式化时注意配套接口 |
| `std::intptr_t` | 需要把指针值保存到整数中 | 条件提供，不要滥用指针整数转换 |
| `std::uintptr_t` | 指针哈希、底层调试、系统接口 | 条件提供，不能替代真实指针语义 |

### 10.3 `<cstddef>` 和字节相关类型选择表

| 类型 | 推荐使用场景 | 注意事项 |
|---|---|---|
| `std::size_t` | `sizeof` 结果、对象大小、容器大小、数组索引 | 无符号，反向循环和减法要小心 |
| `std::ptrdiff_t` | 指针差值、可能为负的索引差、迭代器差值 | 只对同一数组内指针相减有意义 |
| `std::nullptr_t` | 需要把 `nullptr` 作为类型参与重载或模板 | 普通代码通常直接写 `nullptr` |
| `std::byte` | 原始字节、内存块、二进制缓冲区 | 不是整数，运算需显式转换 |
| `std::max_align_t` | 手写内存分配器、对齐相关底层代码 | 日常业务很少直接使用 |

### 10.4 `<stdfloat>` 浮点别名选择表

| 类型 | 推荐使用场景 | 注意事项 |
|---|---|---|
| `std::float16_t` | 半精度存储、GPU/AI/图形数据 | C++23，条件提供，精度很低 |
| `std::float32_t` | 明确依赖 32 位扩展浮点格式 | 条件提供，不是 `float` 的简单别名 |
| `std::float64_t` | 明确依赖 64 位扩展浮点格式 | 条件提供，不是 `double` 的简单别名 |
| `std::float128_t` | 高精度数值计算、科学计算 | 条件提供，性能和库支持差异大 |
| `std::bfloat16_t` | 机器学习、AI 推理训练中的 bfloat16 数据 | 条件提供，精度特征不同于 IEEE binary16 |

### 10.5 常用默认选择

如果没有特殊约束，可以先采用这组默认选择：

```cpp
int          // 普通整数
double       // 普通浮点数
bool         // 布尔值
char         // 普通窄字符
std::string  // 普通字符串，注意它是标准库类型，不是基本类型
nullptr      // 空指针
std::size_t  // 对象大小、容器大小、数组索引
```

如果遇到跨平台二进制协议、文件格式、网络协议、硬件接口、精确内存布局，再使用：

```cpp
std::int32_t
std::uint32_t
std::int64_t
std::uint64_t
std::byte
char8_t
char16_t
char32_t
```

如果遇到性能、存储、数值格式有明确要求的浮点场景，再考虑：

```cpp
float
double
long double
std::float16_t
std::float32_t
std::float64_t
std::float128_t
std::bfloat16_t
```

其中 `<stdfloat>` 的类型必须先确认编译器和标准库支持。

## 11. 总结

C++ 基本数据类型可以记成六条主线：

1. `void` 表示没有值，常用于无返回值函数和 `void*`。
2. `std::nullptr_t` 是 `nullptr` 的类型，现代 C++ 应该用 `nullptr` 表示空指针。
3. 字符类型本质上也有整数行为，但使用语义上要区分字符、字节和编码单元。
4. 整数类型的大小不是完全固定的，需要固定宽度时用 `<cstdint>` 中的类型别名。
5. `int32_t`、`uint64_t`、`size_t`、`ptrdiff_t` 等不是新的基本类型，而是标准库提供的类型别名。
6. C++23 的 `<stdfloat>` 提供固定宽度浮点类型别名，但它们是条件提供的扩展浮点类型别名，不是 `float`、`double` 的简单重命名。

这样既能保持日常代码简单，也能在需要精确表达时避免类型歧义。
